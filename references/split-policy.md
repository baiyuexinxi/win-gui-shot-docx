# SPLIT 执行策略

> 适用：`verify2.ps1` 返回 `ACT=SPLIT`（内容超过一屏，顶部被滚出）时的处理规则。

## 核心结论

**SPLIT 不能由驱动自动决定。**
驱动只检测得到“顶部丢了”，而“从哪切”需要理解脚本语义
（例：`w <- find_words(...)` 与 `head(w, 8)` 必须分居两句，不能拦腰砍断）。
因此权责按下面划分。

## 规则

| 编号 | 规则 | 执行者 |
|:---|:---|:---|
| R1 | 检测到 `HEAD-LOST` / `HEAD-DEEP` → 驱动**不得**自动拆图，只上报 `NEEDS_BLOCK_SPLIT` | 驱动 |
| R2 | 在**语义边界**拆块（定义块 / 调用块），每块 ≤ 8 行、产出 ≤ 1 屏 | 作者层 |
| R3 | 同一会话内顺序采集；块间只清屏、不重启，变量延续 | 驱动 |
| R4 | 命名 `name.1` / `name.2`；图注标 `(1/2)`、`(2/2)`；第二块首行加 `# 续：` | 作者层 + 文档层 |
| R5 | **禁止**用缩小字号、删减输出、拼接图片来“消除”溢出；确需删减必须在正文写明 | 硬性 |
| R6 | 单个 item 最多拆 2 块；超过说明该题应重写成更短的演示 | 驱动 |

## 为什么不允许自动缩字号

自动缩字号看起来是“解决了”，实质是把**可读性**换成了**通过率**：
图能过机检，人却看不清。属于作弊式达标，与“截图是为了让人看懂”的初衷相反。

## 驱动侧的契约

```
item -> capture -> verify
  OK              -> 收
  RETRY           -> 重采（预算 1 次）
  RETRY 且预算用尽 -> FAIL
  SPLIT           -> NEEDS_BLOCK_SPLIT（交回作者层）
```

驱动不实现“拆”，只实现“发现需要拆”。这样驱动可以保持很薄，
而拆分策略随内容变化，不必写进代码。
